# 代码结构规划

## 2. 分层职责

| 层级 | 目录 | 职责 | 不允许 |
|---|---|---|---|
| Router / Controller | `api/routes` | 接收 HTTP、鉴权、参数校验、ownership 检查、响应转换 | 不直接调用 ASR / LLM / TTS；不写复杂业务逻辑 |
| Dependencies | `api/deps.py` | 注入 DB session、当前用户、request_id、配置 | 不做业务状态流转 |
| Use Case | `application/use_cases` | 完成一次用户动作的流程编排 | 不感知 HTTP request / response |
| Orchestrator | `application/conversation_orchestrator.py` | 编排 ASR -> LLM -> TTS 单轮语音链路 | 不做历史统计和报告详情生成 |
| Domain Service | `domain/services` | 单模块业务规则、状态校验、分数规则 | 不直接处理 HTTP；不直接依赖前端展示 |
| Domain Model | `domain/models` | SQLAlchemy / SQLModel 表实体 | 不写 provider 调用 |
| Repository | `infrastructure/repositories` | 数据库读写和查询封装 | 不写跨模块业务流程 |
| Provider Client | `infrastructure/providers` | 第三方 ASR / LLM / TTS 调用、mock、错误归一化 | 不判断 session 状态 |
| Storage | `infrastructure/storage` | S3 / MinIO 上传、签名 URL、删除对象 | 不做评分 |
| Queue | `infrastructure/queue` | RabbitMQ 发布报告任务 | 不生成报告内容 |
| Schemas / DTO | `schemas` | Pydantic 请求、响应、报告 JSON 校验 | 不访问数据库 |
| Worker | `workers` | Celery 消费报告任务、调用 Assessment Service | 不处理实时对话请求 |

| 模块 | Router | Use Case / Orchestrator | Service | Repository / Infra | Schema |
|---|---|---|---|---|---|

## 4. 调用规则

```text
Router -> Use Case -> Domain Service -> Repository / Provider / Storage
Worker -> Use Case / Domain Service -> Repository / Provider
```

禁止调用：

- Router 调 Router。
- Router 直接调用 Provider Client。
- Provider Client 直接写数据库。
- Repository 调用 Service。
- 前端绕过 API 直连对象存储私有 bucket。

## 5. 命名规则

| 类型 | 规则 | 示例 |
|---|---|---|
| Python 文件 | snake_case | `confirm_user_turn.py` |
| Pydantic 入参 | 动词 + `Request` | `ConfirmTurnRequest` |
| Pydantic 出参 | 动词 + `Response` | `ConfirmTurnResponse` |
| Service | 模块名 + `Service` | `PracticeSessionService` |
| Repository | 模型名 + `Repository` | `ConversationTurnRepository` |
| Use Case 函数 | 动词短语 | `confirm_user_turn(command)` |
| 错误码 | UPPER_SNAKE_CASE | `SESSION_NOT_IN_PROGRESS` |
| 数据库表 | plural snake_case | `practice_sessions` |

## 7. 前端调用规则

- 页面只组合 feature 组件，不直接写复杂 API 调用。
- API 请求统一走 `lib/api/client.ts`。
- 匿名身份统一由 `lib/auth/anonymousIdentity.ts` 创建、保存和恢复。
- 前端本地只允许保存 `anonymous_id`、`anonymous_secret`、`access_token` 和可选的 `current_session_id`；transcript、报告、分数、音频对象 key 等业务数据统一由后端持久化。
- 录音能力统一封装在 `lib/audio/recorder.ts`，页面不得直接操作 `RecordRTC`。
- SSE 统一封装在 `lib/sse/practiceEvents.ts`，断开后由页面降级轮询 REST。
- 练习页复杂状态统一进入 Redux Toolkit `practiceSlice`。
