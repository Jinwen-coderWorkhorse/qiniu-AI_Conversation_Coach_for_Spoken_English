# 五人并行开发任务拆分

编写日期：2026-06-07  
适用范围：AI 英语口语陪练 MVP，按 mock provider 优先开发。  
目标：让 5 名工程师并行编码，减少互相等待，最终跑通“选择场景 -> 开始练习 -> 按住说话 -> transcript 确认 -> AI mock 回复 -> 结束练习 -> 报告 -> 历史”的完整闭环。

## 1. 角色分工总览

| 人员 | 角色 | 主责 | 主要交付物 |
|---|---|---|---|
| 工程师 A | 后端基础与数据负责人 | 后端脚手架、数据库、Auth、Scenario、Session 基础接口 | FastAPI 基础工程、migration、seed、Auth / Scenario / Session API |
| 工程师 B | 后端对话链路负责人 | Mock ASR / LLM / TTS、User Turn、Conversation Orchestrator、Media、Report、History | 用户语音 turn 接口、mock provider、报告 worker、历史接口 |

## 2. 基本协作原则

- 先 mock 后真实 provider：首轮开发只接 mock ASR / LLM / TTS，不等待真实云服务。
- API 契约先行：接口字段以 [03-接口详细定义.md](03-接口详细定义.md) 为准，变更必须同步给工程师 E。
- 后端先保证接口可跑，前端先按契约并行接入，联调时再收敛字段细节。
- REST 响应是最终结果来源，SSE 只做进度提示；前端刷新后用 REST 恢复数据。
- 前端本地不持久化业务数据，只保存匿名身份、token 和可选当前 session ID。
- 每个人对自己模块的单元测试 / mock 数据负责，工程师 E 负责主流程 E2E 和合并节奏。

### 4.3 Mock 行为要求

| 能力 | Mock 规则 |
|---|---|
| ASR | 接收任意音频，返回固定或按场景变化的 transcript、`asr_confidence=0.91`、基础 metrics |
| ASR 低置信 | 支持通过请求参数 / 环境变量 / 特定 mock 文件名触发 `asr_confidence=0.52` |
| LLM Reply | 根据 scenario 和 turn_index 返回角色内短句，一次只问一个问题 |
| TTS | 返回固定静态音频 URL；如果没有音频文件，允许返回 `audio_url=null` 并让前端继续 |
| Report | 返回固定结构化报告 JSON，包含总分、4 项细分分、1 条发音建议、1 条表达建议 |

### 4.4 交付标准

- 不接真实 provider 也能跑通完整后端主链路。
- 重复上传同一 `client_turn_id` 不生成重复 turn。
- 重复 confirm 不重复生成 AI turn。
- 结束练习后 report 从 `pending` 变成 `completed`。
- 历史列表和长期数据能看到完成后的 session。

### 4.5 依赖与协作

- 依赖工程师 A 的表结构、repository、session 基础服务。
- 向工程师 D 提供练习页需要的 turn / confirm / discard / end API。
- 向工程师 C 提供 report / history API。
- 与工程师 E 对齐 mock 数据和 E2E 场景。

## 11. MVP 联调验收清单

交付给演示前，5 人共同确认：

- 首页能展示 3 个场景。
- 匿名用户创建 / 恢复正常。
- 选择场景后进入开练确认页。
- 点击开始后创建 session 并进入语音对话页。
- 按住说话有录音态和波形。
- 松开后 mock ASR 返回 transcript。
- 低置信 mock 能展示建议重说。
- 点击确认后 mock AI 回复文本和音频降级逻辑正常。
- 至少能连续完成 6 轮对话。
- 点击结束后生成 mock 报告。
- 报告总览展示总分、水平描述、一句话总结、4 项细分分。
- 改进详情展示 1 条发音建议和 1 条语法 / 表达建议。
- 历史侧边栏展示最近练习和长期数据。
- 页面刷新后能用 session ID 从后端恢复练习 / 报告。
- Playwright 主流程 E2E 通过。
