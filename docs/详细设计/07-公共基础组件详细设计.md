## 2. 全局鉴权逻辑

### 2.1 匿名身份创建

```text
前端生成 anonymous_id + anonymous_secret
  -> POST /auth/anonymous
  -> 后端不存在则创建 user，并保存 secret hash
  -> 后端存在则校验 secret
  -> 签发 7 天 JWT
```

规则：

- 后端不保存 `anonymous_secret` 明文。
- JWT payload 至少包含 `sub=user_id`、`exp`、`iat`。
- JWT 默认有效期 604800 秒。
- token 过期后前端重新调用 `/auth/anonymous`。

### 2.2 业务接口鉴权

- 除 `/auth/anonymous` 外，所有业务接口必须携带 Bearer token。
- Router 通过 `get_current_user` 获取当前用户。
- 涉及 session、turn、report 的接口必须校验 ownership。
- SSE 建连时同样校验 token 和 session ownership。

## 3. 全局异常处理

### 3.1 错误响应格式

```json
{
  "error": {
    "code": "SESSION_NOT_IN_PROGRESS",
    "message": "当前练习已结束。",
    "request_id": "req_123"
  }
}
```

### 3.2 异常分类

| 异常类型 | 处理方式 |
|---|---|
| 参数校验错误 | 转换为 `VALIDATION_ERROR`，HTTP 422 |
| 鉴权失败 | `UNAUTHORIZED`，HTTP 401 |
| 权限失败 | `FORBIDDEN`，HTTP 403 |
| 资源不存在 | `NOT_FOUND`，HTTP 404 |
| 业务状态冲突 | `CONFLICT` 或模块专用错误码，HTTP 409 |
| Provider 失败 | 转换为 `ASR_FAILED`、`LLM_FAILED`、`TTS_FAILED` |
| 未预期异常 | `INTERNAL_ERROR`，HTTP 500，日志记录堆栈但不返回内部细节 |

### 3.3 降级不是异常的场景

| 场景 | HTTP | 响应 |
|---|---:|---|
| ASR 低置信 | 200 | `needs_retry=true`，提示建议重说 |
| TTS 失败但 AI 文本可用 | 200 | `ai_turn.audio_url=null`，前端展示文本继续 |
| 报告 pending | 200 | `status=pending` |
| 报告 failed | 200 | `status=failed` 和错误提示 |

## 4. 统一限流与成本控制

| 限制 | 默认值 | 配置项 |
|---|---:|---|
| 单用户每日 session 数 | 20 | `MAX_DAILY_SESSIONS_PER_USER` |
| 单用户每日 user turn 数 | 120 | `MAX_DAILY_USER_TURNS_PER_USER` |
| 单次练习最长时间 | 10 分钟 | `MAX_SESSION_MINUTES` |
| 单轮录音最长时间 | 60 秒 | `MAX_AUDIO_DURATION_SECONDS` |
| 单轮音频最大大小 | 20MB | `MAX_AUDIO_UPLOAD_MB` |
| Provider 重试次数 | 2 | `PROVIDER_MAX_RETRIES` |

MVP 阶段限流可先用 MySQL 查询当天记录实现，不引入 Redis。后续需要更高并发时再升级为 Redis / API Gateway 限流。

## 5. Provider Client 设计

### 5.1 接口边界

```python
class AsrClient:
    async def transcribe(audio_file, mime_type: str) -> AsrResult: ...

class LlmClient:
    async def generate_reply(prompt: str, context: list[dict]) -> str: ...
    async def generate_report(prompt: str, context: dict) -> dict: ...

class TtsClient:
    async def synthesize(text: str, voice: str) -> TtsResult: ...
```

### 5.2 统一结果

| Client | 统一返回 |
|---|---|
| ASR | `transcript`、`confidence`、`word_confidences`、`speech_rate_wpm`、`pause_count`、`duration_ms` |
| LLM Reply | `text`、`raw_provider_response` 可选 |
| LLM Report | JSON dict，后续必须通过 `ReportSchema` |
| TTS | `audio_bytes`、`mime_type`、`duration_ms` |

### 5.3 错误与重试

- 超时、429、5xx 可重试，最多 2 次。
- 4xx 参数类错误不重试。
- Provider 原始错误不直接暴露给前端。
- mock provider 使用同一接口，靠 `AI_PROVIDER=mock` 切换。

## 6. 存储组件设计

### 6.1 对象 key

```text
users/{user_id}/sessions/{session_id}/turns/{turn_id}/user.webm
users/{user_id}/sessions/{session_id}/turns/{turn_id}/ai.mp3
```

### 6.2 访问策略

- 用户原始音频和 AI 合成音频均保存到私有 bucket。
- 前端只拿短期签名 URL。
- 签名 URL 默认有效期不超过 15 分钟。
- 日志不记录完整签名 URL。
- 删除历史时异步删除对象。

## 7. 队列与 Worker 设计

| 组件 | 职责 |
|---|---|
| `report_publisher.py` | 在结束练习后发布 `session_id`、`report_id` |
| RabbitMQ | 只承载报告任务队列 |
| `report_worker.py` | 消费任务，读取 transcript，调用 Assessment，写入报告 |

任务幂等规则：

- `assessment_reports.session_id` 唯一。
- Worker 只处理 `status=pending` 的报告。
- 同一 `session_id` 重复投递时不会生成多份报告。
- Worker 失败后写入 `status=failed`、`error_code`、`error_message`。

## 8. 日志与监控

### 8.1 日志字段

| 字段 | 说明 |
|---|---|
| `request_id` | 请求链路 ID |
| `user_id` | 当前用户 ID，可脱敏 |
| `session_id` | 当前练习 ID |
| `turn_id` | 当前 turn ID |
| `provider` | ASR / LLM / TTS provider |
| `duration_ms` | 当前步骤耗时 |
| `error_code` | 统一错误码 |

### 8.2 禁止记录

- 完整 transcript。
- 完整音频签名 URL。
- `anonymous_secret` 明文。
- Provider API key。

### 8.3 关键耗时指标

- 上传到 ASR 返回 transcript。
- confirm 到 LLM 文本返回。
- confirm 到 TTS 音频可播放。
- 报告任务创建到 completed。
- SSE 断开和重连次数。

## 10. 数据访问通用规则

- Repository 查询默认过滤 `deleted_at is null`。
- 软删除历史时必须在事务内标记 session、turn、report。
- 所有涉及 session 的查询必须带 `user_id` ownership 条件或由上层先完成 ownership 校验。
- 更新状态时尽量使用条件更新，例如只允许 `pending -> confirmed`、`in_progress -> reporting`。
- 生成报告和结束 session 的事务边界必须清晰，避免 session 已结束但 report 未创建。
