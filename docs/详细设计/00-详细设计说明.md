## 2. 总体约束

| 约束项 | 详细设计采用 |
|---|---|
| 技术栈 | Next.js、shadcn/ui、Redux Toolkit、RecordRTC、FastAPI、SQLAlchemy / SQLModel、MySQL、RabbitMQ + Celery、S3 / MinIO |
| 通信方式 | REST 为主契约，SSE 只承载进度事件和恢复辅助 |
| 业务主键 | 业务记录使用应用层 UUID 字符串；固定场景使用稳定 `slug` |
| 数据库 | MySQL、InnoDB、`utf8mb4` 字符集 |
| 时间字段 | 业务表统一使用 `created_at`、`updated_at`；可删除业务数据增加 `deleted_at` |
| 软删除 | 用户历史删除时先标记 `deleted_at`，再异步删除 S3 / MinIO 音频对象 |
| 音频隐私 | 私有 bucket 保存，后端生成短期签名 URL |
| 评分时机 | 对话中不显性纠错，课后生成结构化报告 |
| ASR 低置信 | 低于 0.65 建议重说，0.65 到 0.8 进入评分但降权 |

## 4. MVP 模块边界

MVP 保留总体设计中的 5 张表和 9 类核心后端能力：Auth、Scenario、Practice Session、Conversation Orchestrator、Media、Assessment、History、Provider Clients、Report Worker。

实时对话主链路由 FastAPI 同步返回主结果：

```text
上传语音 -> ASR transcript -> 用户确认 -> LLM 角色回复 -> TTS 音频 -> 返回 AI turn
```

课后报告链路异步执行：

```text
结束练习 -> 创建 pending report -> RabbitMQ -> Celery Worker -> Assessment -> completed / failed
```
