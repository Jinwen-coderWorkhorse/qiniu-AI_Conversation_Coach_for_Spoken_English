# 接口详细定义

Base URL：`/api/v1`  
认证方式：除 `POST /auth/anonymous` 外，均使用 `Authorization: Bearer <token>`。  
接口维护建议：以本文件为初始契约，同步录入 Apifox / Swagger，并在实现后导出 `packages/contracts/openapi.json`。

## 1. 全局约定

### 1.1 请求头

| Header | 类型 | 必传 | 说明 |
|---|---|---|---|
| Authorization | string | 业务接口必传 | `Bearer <jwt_token>` |
| Content-Type | string | 必传 | JSON 接口使用 `application/json`；音频上传使用 `multipart/form-data` |
| X-Request-Id | string | 可选 | 前端生成的请求 ID；未传时后端生成 |

### 1.2 通用错误响应

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请求参数不合法。",
    "request_id": "req_123"
  }
}
```

### 1.3 全局错误码

| 错误码 | HTTP 状态 | 说明 |
|---|---:|---|
| `UNAUTHORIZED` | 401 | 未登录、token 过期或 token 无效 |
| `FORBIDDEN` | 403 | 当前用户无权访问该资源 |
| `NOT_FOUND` | 404 | 资源不存在或已删除 |
| `VALIDATION_ERROR` | 422 | 请求参数不合法 |
| `RATE_LIMITED` | 429 | 超过每日 session / turn 限制 |
| `CONFLICT` | 409 | 状态冲突或幂等冲突 |
| `SCENARIO_NOT_FOUND` | 404 | 场景不存在或已下架 |
| `SESSION_NOT_IN_PROGRESS` | 409 | 当前练习不可继续提交 turn |
| `SESSION_ALREADY_IN_PROGRESS` | 409 | 同一用户已有进行中的练习 |
| `TURN_NOT_FOUND` | 404 | turn 不存在或不属于该 session |
| `TURN_NOT_PENDING` | 409 | turn 已确认、已废弃或不可操作 |
| `AUDIO_REQUIRED` | 422 | 未上传音频文件 |
| `AUDIO_TOO_LARGE` | 413 | 音频超过大小限制 |
| `AUDIO_DURATION_EXCEEDED` | 422 | 音频超过 60 秒 |
| `UNSUPPORTED_AUDIO_TYPE` | 415 | 音频 MIME 不支持 |
| `ASR_FAILED` | 502 | ASR 服务失败 |
| `ASR_LOW_CONFIDENCE` | 200 | 低置信通常作为成功响应中的 `needs_retry` 返回 |
| `LLM_FAILED` | 502 | LLM 生成失败且兜底失败 |
| `TTS_FAILED` | 200 | TTS 失败时优先降级返回文本，`audio_url` 可为空 |
| `REPORT_NOT_READY` | 200 | 报告未完成时返回 `status=pending` |
| `REPORT_FAILED` | 200 | 报告失败时返回 `status=failed` |
| `INTERNAL_ERROR` | 500 | 未预期错误 |

## 2. 接口总览

| 接口 | 方法 | 所属模块 | 调用方 |
|---|---|---|---|
| `/auth/anonymous` | POST | Auth | Web 首次进入 / token 过期恢复 |
| `/scenarios` | GET | Scenario | 首页 |
| `/scenarios/{slug}` | GET | Scenario | 开练确认页 |
| `/practice-sessions` | POST | Practice Session | 开练确认页 |
| `/practice-sessions/{id}` | GET | Practice Session / History | 对话页刷新恢复、历史回看 |
| `/practice-sessions/{id}/user-turns` | POST | Conversation Orchestrator | 对话页 |
| `/practice-sessions/{id}/turns/{turn_id}/confirm` | POST | Conversation Orchestrator | Transcript 确认弹层 |
| `/practice-sessions/{id}/turns/{turn_id}/discard` | POST | Practice Session | Transcript 重说 |
| `/practice-sessions/{id}/end` | POST | Practice Session / Report | 对话页结束按钮 |
| `/practice-sessions/{id}/report` | GET | Assessment / Report | 报告总览页、改进详情页 |
| `/practice-sessions` | GET | History | 侧边栏历史 |
| `/me/stats` | GET | History | 侧边栏长期数据 |
| `/practice-sessions/{session_id}/events` | GET | SSE | 对话页、报告等待页 |

## 3. 认证与匿名用户

### 3.1 创建或恢复匿名用户

| 项 | 内容 |
|---|---|
| 请求方式 | POST |
| URL | `/api/v1/auth/anonymous` |
| 接口名称 | 创建或恢复匿名用户 |
| 所属模块 | Auth |
| 调用方 | Web App 启动、JWT 过期恢复 |

请求参数：

| 位置 | 字段名 | 类型 | 必传 | 注释 | 枚举值 |
|---|---|---|---|---|---|
| Body | anonymous_id | string | 是 | 前端本地生成并保存的设备级匿名 ID | - |
| Body | anonymous_secret | string | 是 | 前端本地生成并保存的高熵随机 secret | - |

请求示例：

```json
{
  "anonymous_id": "device_generated_uuid",
  "anonymous_secret": "client_generated_random_secret"
}
```

成功响应：

```json
{
  "user": {
    "id": "uuid",
    "anonymous_id": "device_generated_uuid"
  },
  "access_token": "jwt_token",
  "expires_in": 604800
}
```

错误场景：

| 错误码 | 触发条件 | 提示 |
|---|---|---|
| `VALIDATION_ERROR` | `anonymous_id` 或 `anonymous_secret` 缺失 | 请求参数不合法 |
| `UNAUTHORIZED` | `anonymous_id` 已存在但 secret 校验失败 | 匿名身份校验失败 |

### 5.3 上传用户语音并完成 ASR

| 项 | 内容 |
|---|---|
| 请求方式 | POST |
| URL | `/api/v1/practice-sessions/{id}/user-turns` |
| 接口名称 | 上传用户一轮语音 |
| 所属模块 | Conversation Orchestrator |
| 调用方 | 语音对话页 |

请求参数：

| 位置 | 字段名 | 类型 | 必传 | 注释 | 枚举值 |
|---|---|---|---|---|---|
| Header | Authorization | string | 是 | Bearer token | - |
| Path | id | string | 是 | session UUID | - |
| Form | audio | file | 是 | 用户录音文件 | - |
| Form | client_turn_id | string | 是 | 前端幂等 ID | - |
| Form | duration_ms | number | 是 | 录音时长，毫秒 | `<=60000` |
| Form | mime_type | string | 是 | 浏览器录音 MIME | `audio/webm` / `audio/mp4` / provider 支持类型 |

成功响应：

```json
{
  "turn": {
    "id": "uuid",
    "turn_index": 2,
    "speaker": "user",
    "transcript": "My name is Alex. I worked on a shopping app.",
    "asr_confidence": 0.91,
    "needs_retry": false,
    "metrics": {
      "duration_ms": 6200,
      "word_count": 11,
      "speech_rate_wpm": 106,
      "pause_count": 2
    }
  }
}
```

低置信成功响应：

```json
{
  "turn": {
    "id": "uuid",
    "turn_index": 2,
    "speaker": "user",
    "transcript": "I work ... shopping ...",
    "asr_confidence": 0.52,
    "needs_retry": true
  },
  "hint": "识别不太确定，建议重说一次。"
}
```

错误场景：

| 错误码 | 触发条件 | 提示 |
|---|---|---|
| `SESSION_NOT_IN_PROGRESS` | session 已结束或正在生成报告 | 当前练习已结束 |
| `AUDIO_REQUIRED` | 未上传音频 | 请重新录音 |
| `AUDIO_TOO_LARGE` | 文件超过 20MB | 音频太大，请缩短录音 |
| `AUDIO_DURATION_EXCEEDED` | 时长超过 60 秒 | 单次最多录 60 秒 |
| `UNSUPPORTED_AUDIO_TYPE` | MIME 不支持且无法转码 | 当前浏览器录音格式暂不支持 |
| `ASR_FAILED` | ASR 调用失败且重试失败 | 识别失败，请重试 |
| `RATE_LIMITED` | 超过每日 120 个 user turn | 今日练习轮次已达上限 |

### 5.4 确认 transcript 并生成 AI 回复

| 项 | 内容 |
|---|---|
| 请求方式 | POST |
| URL | `/api/v1/practice-sessions/{id}/turns/{turn_id}/confirm` |
| 接口名称 | 确认用户 turn |
| 所属模块 | Conversation Orchestrator |
| 调用方 | TranscriptReview |

请求参数：

| 位置 | 字段名 | 类型 | 必传 | 注释 | 枚举值 |
|---|---|---|---|---|---|
| Header | Authorization | string | 是 | Bearer token | - |
| Path | id | string | 是 | session UUID | - |
| Path | turn_id | string | 是 | user turn UUID | - |
| Body | accepted | boolean | 是 | 是否确认 transcript | `true` |

请求示例：

```json
{
  "accepted": true
}
```

成功响应：

```json
{
  "status": "ai_reply_ready",
  "user_turn_id": "uuid",
  "ai_turn": {
    "id": "uuid",
    "turn_index": 3,
    "speaker": "ai",
    "text": "Thanks, Alex. Could you tell me more about your role in that project?",
    "audio_url": "https://private-signed-url",
    "audio_mime_type": "audio/mpeg"
  },
  "current_step_no": 2
}
```

错误场景：

| 错误码 | 触发条件 | 提示 |
|---|---|---|
| `TURN_NOT_FOUND` | turn 不存在或不属于 session | 识别结果不存在 |
| `TURN_NOT_PENDING` | turn 已确认或已废弃 | 该识别结果已处理 |
| `SESSION_NOT_IN_PROGRESS` | session 不可继续 | 当前练习已结束 |
| `LLM_FAILED` | LLM 失败且兜底失败 | AI 回复失败，请重试 |
| `TTS_FAILED` | TTS 失败 | 返回 AI 文本并允许继续，`audio_url` 为空 |

特殊规则：

- 重复确认同一个 turn 时返回已有 AI turn，不重复生成回复。
- 本接口是 AI 回复主结果来源；SSE 只用于进度显示。

### 5.6 结束练习

| 项 | 内容 |
|---|---|
| 请求方式 | POST |
| URL | `/api/v1/practice-sessions/{id}/end` |
| 接口名称 | 结束练习并触发报告生成 |
| 所属模块 | Practice Session / Assessment |
| 调用方 | 对话页结束按钮 |

请求参数：

| 位置 | 字段名 | 类型 | 必传 | 注释 | 枚举值 |
|---|---|---|---|---|---|
| Header | Authorization | string | 是 | Bearer token | - |
| Path | id | string | 是 | session UUID | - |
| Body | reason | string | 是 | 结束原因 | `user_finished` / `timeout` |

请求示例：

```json
{
  "reason": "user_finished"
}
```

成功响应：

```json
{
  "session_id": "uuid",
  "status": "reporting",
  "report_id": "uuid"
}
```

错误场景：

| 错误码 | 触发条件 | 提示 |
|---|---|---|
| `NOT_FOUND` | session 不存在 | 练习不存在 |
| `FORBIDDEN` | session 不属于当前用户 | 无权访问 |
| `CONFLICT` | 无任何 confirmed 用户 turn | 暂无可生成报告的内容 |

特殊规则：

- 重复结束同一个 session 时返回已有 `report_id`。
- 结束接口在同一事务中把 session 置为 `reporting` 并创建 `assessment_reports(status=pending)`。

## 8. SSE 事件接口

### 8.1 订阅练习进度事件

| 项 | 内容 |
|---|---|
| 请求方式 | GET |
| URL | `/api/v1/practice-sessions/{session_id}/events` |
| 接口名称 | 订阅练习 / 报告进度 |
| 所属模块 | SSE |
| 调用方 | 对话页、报告等待页 |

请求参数：

| 位置 | 字段名 | 类型 | 必传 | 注释 | 枚举值 |
|---|---|---|---|---|---|
| Header | Authorization | string | 是 | Bearer token | - |
| Path | session_id | string | 是 | session UUID | - |

事件列表：

| 事件 | payload | 说明 |
|---|---|---|
| `ai.generating` | `{ "turn_id": "uuid" }` | AI 正在生成回复 |
| `ai.text.delta` | `{ "text": "Could you..." }` | 可选 AI 文本流 |
| `ai.text.done` | `{ "turn_id": "uuid", "text": "..." }` | AI 文本完成 |
| `ai.audio.ready` | `{ "turn_id": "uuid", "audio_url": "..." }` | AI 音频可播放 |
| `practice.step.changed` | `{ "current_step_no": 2 }` | 任务步骤变化 |
| `report.ready` | `{ "report_id": "uuid" }` | 报告生成完成 |
| `error` | `{ "code": "...", "message": "..." }` | 错误事件 |

错误场景：

| 错误码 | 触发条件 | 提示 |
|---|---|---|
| `UNAUTHORIZED` | token 无效 | 请重新进入应用 |
| `FORBIDDEN` | session 不属于当前用户 | 无权订阅该练习 |
| `NOT_FOUND` | session 不存在 | 练习不存在 |

特殊规则：

- SSE 不承载客户端指令。
- SSE 不是最终结果唯一来源；断开后前端通过 REST 查询恢复。
